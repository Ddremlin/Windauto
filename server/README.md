# Сервер Windauto

Общая база заказов и фото для сотрудников — отдельная для каждой компании: компании регистрируются сами,
у каждой свои сотрудники, заказы, нумерация и фото. Node.js 24 + SQLite (единственная зависимость — Anthropic SDK для распознавания);
HTTPS через Caddy (сертификат Let's Encrypt выпускается сам).

## Установка на VPS

Нужен VPS с Ubuntu 22.04/24.04 или Debian 12 (1 ядро, 1 ГБ RAM достаточно), открытые порты 80 и 443.

```bash
scp -r server root@<IP>:/opt/windauto
ssh root@<IP> 'bash /opt/windauto/install.sh'
```

Скрипт поставит Docker, запустит сервер и выведет адрес (`https://<IP>.sslip.io`) и пароль администратора.
Свой домен: `bash install.sh api.example.pl` (DNS-запись A должна указывать на IP сервера).

## В приложении

Настройки → «Общая база» → адрес сервера, логин `admin`, пароль из вывода установки.
Это владелец платформы: в настройках у него есть список всех компаний (блокировка, удаление).
Администратор компании добавляет сотрудников там же, в разделе «Сотрудники»: с логином и паролем
или приглашением по email (сотрудник сам задаёт пароль по ссылке из письма).

## Компании и письма

Новая компания регистрируется в приложении (Настройки → «Общая база» → «Зарегистрировать компанию»):
название, email, пароль. Войти можно после подтверждения email по ссылке из письма.
«Забыли пароль?» присылает ссылку на новый пароль. Ссылки из писем открывают страницы этого сервера
(`/auth/verify`, `/auth/reset`), политика конфиденциальности и условия — `/legal/privacy`, `/legal/terms`.

Письма отправляются через Brevo; без ключа сервер работает, но письма только пишутся в журнал
(`docker compose logs api` — там же ссылки, их можно переслать вручную). В `/opt/windauto/.env`:

```
PUBLIC_URL=https://app.windauto.pl      # адрес сервера в ссылках из писем
BREVO_API_KEY=xkeysib-...
MAIL_FROM=noreply@windauto.pl           # домен должен быть подтверждён в Brevo
MAIL_FROM_NAME=Windauto
OPERATOR_NAME=Imię Nazwisko             # оператор сервиса — для политики и условий
OPERATOR_ADDRESS=ul. …, 00-000 Miasto
OPERATOR_NIP=0000000000
OPERATOR_EMAIL=kontakt@windauto.pl
SUPPORT_EMAIL=help@windauto.pl          # куда приходят сообщения из «Помощь» (без него — на OPERATOR_EMAIL)
TELEGRAM_BOT_TOKEN=123456:ABC...         # бот от @BotFather — сообщения из «Помощь» в Telegram
TELEGRAM_CHAT_ID=123456789               # кому бот пишет (ваш id или id группы)
# REGISTRATION=off                      # закрыть регистрацию новых компаний
```

## Распознавание VIN, номера и техпаспорта по фото

Кнопка камеры у полей VIN и номера и кнопка «Техпаспорт» отправляют снимок на сервер, сервер — в Claude (Anthropic API).
Включается ключом в `/opt/windauto/.env`:

```
ANTHROPIC_API_KEY=sk-ant-...
```

затем `docker compose up -d`. Модель по умолчанию `claude-opus-5-5`, сменить — `AI_MODEL=...`.

## Безопасность

- Удалённые заказы 30 дней лежат в корзине (Синхронизация → «Корзина», только администратор) — их можно вернуть.
  Сотрудник удаляет только свои заказы и не больше 20 в час; чужие возвращаются к нему на телефон.
- Заказ больше 1 МБ не принимается; база заказов компании — до `ORG_DB_MB` (500 МБ).
- Вход, которым не пользовались `SESSION_IDLE_DAYS` дней (30), закрывается; «Выйти на всех других устройствах» — в разделе синхронизации.
- Подбор пароля к аккаунту блокирует новые адреса, но не те, откуда владелец уже входил.
- Порт 8080 наружу не открывать: адрес клиента сервер берёт из `X-Forwarded-For`, который выставляет Caddy.
- `PUBLIC_URL` задать обязательно; `ADMIN_PASSWORD` из `.env` после первого запуска удалить;
  для копий — `BACKUP_PASSPHRASE` и `BACKUP_COPY_TO` (см. `backup.sh`).

## Тарифы и оплата (Stripe)

Бесплатно: заказы, документы, до 2 сотрудников, 1 ГБ фото (`FREE_QUOTA_GB`). Pro: ИИ (до `AI_PER_MONTH`=500 в месяц),
видео, 50 ГБ (`ORG_QUOTA_GB`), сотрудники без ограничения, логотип в PDF, отзывы, выгрузка CSV, вся история.
Новая компания — 14 дней Pro (`orgs.trial_until`), за 3 дня до конца — письмо владельцу. Владелец платформы может
включить Pro навсегда или выдать пробные дни (Синхронизация → Компании; `PATCH /api/platform/orgs/:id {pro, trialDays}`).

Оплата — Stripe Checkout (подписка, карта и BLIK), управление — портал Stripe. Настройка:

1. Stripe → Products: продукт «Windauto Pro», две цены в PLN — 79 в месяц и 790 в год (повторяющиеся). ID цен `price_…`.
2. Settings → Payment methods: включить карты и BLIK; для автопродления BLIK запросить «BLIK recurring payments».
3. Developers → Webhooks: эндпоинт `https://<домен>/api/billing/webhook`, события `checkout.session.completed`,
   `customer.subscription.created`, `customer.subscription.updated`, `customer.subscription.deleted`, `invoice.paid`.
4. Settings → Billing → Customer portal: разрешить отмену подписки, смену способа оплаты и просмотр счетов.
5. В `.env`: `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, `STRIPE_PRICE_MONTH`, `STRIPE_PRICE_YEAR`
   (VAT: `STRIPE_TAX_RATE=txr_…` — ставка 23 % из Stripe, или `STRIPE_AUTOMATIC_TAX=1` при Stripe Tax).

Сначала — с тестовыми ключами (`sk_test_…`, карта 4242 4242 4242 4242), потом — боевые.
Подписка → `orgs.paid_until` (конец периода + 3 дня на повторные списания), статус — `orgs.sub_status`.

## Обслуживание

```bash
cd /opt/windauto
docker compose logs -f api        # журнал
docker compose up -d --build      # обновление после замены файлов сервера (*.mjs)
./backup.sh                       # резервная копия вручную (автоматически — каждую ночь в 03:30)
```

Данные: `data/accounts.db` — компании и пользователи; `data/orgs/<id>/` — у каждой компании своя база
(`org.db`: заказы, история, счётчики номеров), `photos/` и `videos/`. Удаление компании стирает её папку целиком.
При первом запуске новой версии старые данные (`data/windauto.db`, `photos/`, `videos/`) переносятся в первую компанию.
В ночной архив видео не входят — они большие; при заданном `BACKUP_COPY_TO` каждое новое видео шифруется отдельно и досылается в папку `videos-enc/` (`<id компании>.<файл>.enc`), удалённые на сервере видео пропадают и из копии. Без `BACKUP_PASSPHRASE` копия вне сервера не делается (backup.sh завершается с ошибкой). Рядом с архивом — `.hmac`: подпись тем же паролем, проверка перед восстановлением: `openssl dgst -sha256 -hmac ПАРОЛЬ -r файл.enc` должно совпасть с содержимым `файл.enc.hmac`. `HEALTHCHECK_URL` в `.env` — адрес проверки healthchecks.io: если копия не сделалась, придёт тревога.

**Защита копий.** Пароль `BACKUP_PASSPHRASE` храните ещё и вне сервера (менеджер паролей): без него копии не расшифровать. Сервер имеет доступ к Storage Box по ключу и может там удалять — поэтому в Hetzner Console включите для Storage Box автоматические снимки (Snapshots, например ежедневно, хранить 14): их нельзя удалить по ssh, и взлом сервера не уничтожит копии.

Фото и видео, на которые не ссылается ни один заказ (в том числе в корзине), сервер раз в сутки удаляет, если они старше 14 дней (`MEDIA_GRACE_DAYS`): так удалённый заказ через 30 дней корзины исчезает с сервера вместе с файлами. Если «без заказа» оказалось больше половины файлов компании (и больше 20), уборка ничего не удаляет и пишет об этом в журнал — после проверки можно задать `MEDIA_SWEEP_FORCE=1` в `.env`. Загруженные фото и видео не перезаписываются.

Сервер в контейнере работает от пользователя `node` (uid 1000): при запуске он забирает себе файлы в `data/`, принадлежащие другим (например, восстановленные из копии от root).
Номера заказов `2026/0001` — свои у каждой компании, счётчик по годам. Ограничения (10 неудачных входов за 15 минут,
5 регистраций в час, 5 писем за 15 минут с одного адреса) хранятся в базе и переживают перезапуск. Копии: `backups/`, хранятся 30 дней.

**Двухфакторный вход** (Настройки → «Включить двухфакторный вход»): код TOTP из приложения-аутентификатора и 8 одноразовых запасных кодов. Потеряны и телефон, и запасные коды — выключить на сервере:
`docker compose exec -T api node -e "const {DatabaseSync}=require('node:sqlite');new DatabaseSync('/data/accounts.db').prepare('UPDATE users SET totp=NULL,totp_recovery=NULL WHERE login=?').run('admin')"`.
Восстановление: остановить (`docker compose down`), распаковать архив во временную папку и разложить:
`backup/accounts.db` → `data/accounts.db`, `backup/orgs/<id>/org.db` → `data/orgs/<id>/org.db`,
`orgs/<id>/photos` → `data/orgs/<id>/photos`; запустить снова. Архив `.enc` сначала расшифровать:
`openssl enc -d -aes-256-cbc -pbkdf2 -iter 200000 -in файл.tar.gz.enc -out файл.tar.gz` (спросит пароль); видео — так же каждое из `videos-enc/`.

## Android-приложение

APK раздаёт этот сервер: `GET /api/app` — версия, `GET /api/app/apk` — файл (оба без входа).
Приложение само проверяет версию при открытии и предлагает «Обновить».
Выпуск новой версии: поднять `version` в `package.json`, собрать `npm run apk`, выложить:

```bash
scp release-apk/windauto.apk release-apk/latest.json root@<IP>:/opt/windauto/data/app/
```

Первую установку на новый телефон — открыть `https://<домен>/api/app/apk` в браузере телефона
и разрешить установку из этого источника.

## API

| Метод | Путь | Назначение |
|---|---|---|
| POST | /api/login | вход по логину или email, выдаёт токен; `code: 'unverified'` — email не подтверждён; `totp_required` / `totp_failed` — нужен код двухфакторного входа (`code`) |
| POST | /api/me/totp/setup | `{password}` → `{secret, uri}` — начать включение двухфакторного входа |
| POST | /api/me/totp/enable | `{code}` → `{recovery}` — включить первым кодом, 8 запасных кодов |
| POST | /api/me/totp/disable | `{password, code}` — выключить |
| POST | /api/register | `{company, name, email, password, lang, accept}` — новая компания, письмо для подтверждения |
| POST | /api/verify/resend | `{email}` — письмо с подтверждением ещё раз |
| POST | /api/password/forgot | `{login}` — письмо со ссылкой на новый пароль |
| GET/PATCH/DELETE | /api/org | своя компания: название; удаление со всеми данными (владелец, `{password}`) |
| GET | /api/platform/orgs | все компании (владелец платформы); PATCH/DELETE /api/platform/orgs/:id — блокировка, удаление |
| GET | /api/sync?since=N | изменения новее N |
| POST | /api/sync | отправка изменений; если заказ меняли параллельно — слияние по полям (`_ft`), результат в `merged`; там же номер для новых заказов |
| GET | /api/events | SSE-уведомления об изменениях (`?ticket=` из POST /api/events/ticket) |
| PUT/GET | /api/photos/:id | фото |
| POST | /api/voice | `{text, elements, works, damages}` (речь, уже переведённая телефоном в текст) → поля заказа и работы по элементам |
| PUT/GET | /api/videos/:id.mp4 | круговое видео приёмки (до 300 МБ, GET поддерживает Range) |
| POST | /api/recognize | `{kind: 'vin'\|'plate'\|'doc', image: base64 JPEG}` → `{value, country?, confident}`, для doc — `{plate, vin, make, model, year, owner, confident}` |
| GET | /api/orders/:id/history | история изменений заказа (кто, когда, какие поля) |
| GET | /api/staff | сотрудники компании для выбора ответственного |
| GET/POST/PATCH/DELETE | /api/users | сотрудники компании (администратор): `{email}` без пароля — приглашение, PATCH `{invite: true}` — ещё раз |
